# 장애·회고 맥락

대상 코드가 방어 코드처럼 보일 때(null 검사, 재시도, 타임아웃, 속도 제한, 기능 플래그, 잠금, 복구 경로, 폴백) 자기 출처 안에서 아래도 찾는다.

- **저장소 결정 기록·계약**: 트러블슈팅 기록 `*/docs/plan/*/trouble-shooting/`, 결정 기록 중 복구·재시도·잠금·폴백을 다룬 것(예: 복구 워커, 회의 잠금), 진행 로그의 "문제", "원인" 절
- **소스 관리**: "fix", "hotfix", "복구", "방어", "revert" 뒤에 "다시 적용" 이 오는 커밋은 강한 신호다. 같은 날 머지된 수정 PR 도 본다
- **GitHub 이슈**: `bug` 같은 라벨, 오류 문자열, "장애", "실패", "멈춤" 같은 말이 들어간 이슈
- **그 밖의 MCP (있을 때)**: 코드가 들어온 날짜 전후의 장애 채널·알림·오류 이벤트
