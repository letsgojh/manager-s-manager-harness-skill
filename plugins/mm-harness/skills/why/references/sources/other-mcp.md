# 그 밖의 MCP (있을 때만)

이 프로젝트는 보통 아래 범주의 MCP 를 쓰지 않는다. 맞는 MCP 가 연결되고 인증돼 있을 때만 MCP 마다 조사자 하나를 띄운다. 없으면 조사자를 띄우지 않고 "참고한 출처" 에 "MCP 없음" 으로 적는다. 팀 논의는 주로 디스코드와 회의에서 하고, 그 결론은 결정 기록이나 이슈로 옮겨진다.

| 범주 | 예 | 가장 잘 찾는 것 |
|---|---|---|
| 실시간 채팅 | Slack, Discord, Teams | 문서에 오르지 않은 실시간 논의. 다른 기록이 얇을 때 특히 중요 |
| 인프라 관측 | Datadog, Grafana, Honeycomb | 코드가 반응한 인프라 신호(타임아웃, 재시도, 속도 제한) |
| 오류 추적 | Sentry, Rollbar | 방어 코드를 부른 특정 예외와 그 흐름 |
| 제품 분석 저장소 | Databricks, BigQuery, Snowflake | 기능 플래그, 실험, 데이터 이전, "이 숫자는 어디서 왔나" |

## 찾는 법

1. **도구 목록부터 본다.** MCP 마다 도구가 다르다. `authenticate` 도구만 보이면 인증되지 않은 것이다. 인증을 시도하지 말고 멈춰서 빈틈으로 보고한다.
2. **기준점으로 좁힌다.** PR 작성자, PR 머지 날짜 전후, PR URL(`/pull/<number>`), 오류 문자열, 대상 코드의 상수·임계값.
3. **스레드와 맥락까지 읽는다.** 채팅 메시지 하나는 스레드 없이 읽으면 다르게 읽힌다. 지표나 오류는 코드가 들어온 시기 전후를 함께 본다.
4. **조회는 읽기만.** 분석 저장소에는 SELECT 만 쓰고, 범위를 좁히고, 쿼리를 그대로 기록한다. 표 이름, 기간, 결과 요약(개수, 백분위, 처음·마지막 시각)을 돌려준다.

## 흔한 함정

- **보존 기간.** 오래된 메시지·로그는 지워졌을 수 있다. 어느 시점 이전이 비어 있으면 그 경계를 적는다.
- **찾을 수 없는 개인 메시지.** 많은 결정이 DM 에서 일어나고 검색되지 않는다. 알려진 한계로 적는다.
- **농담을 결정으로 읽기.** "그냥 그거 하죠" 는 결정이 아니다. 숙고된 논의를 찾는다.
- **인증 실패.** 결과를 지어내지 않는다. 그 출처를 찾을 수 없었다고 보고한다.
